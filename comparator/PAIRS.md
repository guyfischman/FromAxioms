# The pairs, and what each one establishes

Generated by `Comparator/Audit.lean` on every `lake build` in `comparator/`.
Each row is what the kernel answers about one pair.

A PAIR IS CERTIFIED AS MATHLIB'S AND CARRIES NO SURCHARGE UNLESS ITS ROW SAYS
OTHERWISE. `challenge_is_mathlibs` proves the challenge FROM Mathlib, so the
proposition is Mathlib's rather than ours; a pair without that witness is
marked `NOT CERTIFIED`, and one paying beyond both sides carries a
`surcharge` line.

`rests on` counts the propositions proved under `FromAxioms/` that the proof
actually reaches; a pair reaching none has not used this library.

A surcharge is what a pair pays beyond both the tower theorems it uses and
Mathlib's own proof of the same statement. A statement whose vocabulary carries
`Classical.choice` costs it whoever proves it, so that is charged to neither
side.

Generality is NOT here. Comparing two binder lists is a reading rather than a
computation, so `formalization.yaml` carries it per pair, where it can say that
a pair is narrower than what it matches.
